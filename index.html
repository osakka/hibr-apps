hibr apps

The catalogue the apps command installs from — everything the hibr desktop scans for, each one a script you can read before you run it.

Use it

apps list
apps info snake
apps install snake

Installing places a file where the desktop already looks, so it is there the next time the desktop starts: an application under $XDG_DATA_HOME/hibr/apps, a Control Panel pane under control-panel/, and so on for all five kinds. Something that brings its own pane or Control Strip module travels as a tarball and each part is placed in the root it names. apps remove takes it away again, keeping any part another installed app brings too.

The first column is what you install: a name where it means one thing, and kind/name where it does not — clock is both an application and a screen saver, so each is named by its id.

Control Panel panes
control-panel/aboutmeAbout Me0.99.56the Control Panel pane for About Me: the name, the line under it and the picture the login screen shows for you (examples/desktop/login/), and which session it starts. They live in ~/.config/hibr/me.json -- data, never run, since the login screen reads it before anyone has logged in (as you, never as root). The picture is a PNG or JPEG anywhere you can read it; the file keeps its path.
control-panel/appearanceAppearance0.99.56the Control Panel pane for how the desktop looks: the theme (the whole look at once), the colour scheme, the wallpaper (a glyph, or an image chosen in a picker of its own), the menu bar's spacing and notification icon, the shadows, and how dialog buttons look. A theme or a colour scheme sets the variables the window manager already reads every frame, so a change shows on the next one, in every window at once.
control-panel/control-stripControl Strip0.56the Control Panel pane for the strip itself: which side it docks to, and whether it casts its own shadow, the same reasoning as Behaviour's own Window Shadow and Menu Shadow rows. Position, collapse and length are dragged directly on the strip, the same as a window is moved and resized on itself rather than from a settings row -- this pane only carries the two things that are otherwise nowhere to see or change.
control-panel/datetimeDate & Time0.99.67the Control Panel pane for the time, the date, and a small world map with a mark near the machine's own time zone, System 7's Date & Time control panel. A custom pane, since a map needs a body of its own rather than two columns of text.
control-panel/desktopDesktop0.99.179the Control Panel pane for the bare desktop: which icons sit on it, how many workspaces it has, whether Cycle goes through this one's windows or every one's, how often a busy screen is redrawn, and how screenshots are taken and where they go.
control-panel/displaysDisplays0.99.56Control Panel's own picture of a multi-monitor arrangement: a dropdown to choose which display is primary, and every attached display drawn to scale below it from hold clients, dragged to reposition (hold move on release). Right-click a rectangle for Detach (hold drop) or Identify (flash its own name on its own screen, so whoever is looking can tell which is which). The primary display is the picture's own anchor -- every rectangle is positioned relative to it, so switching which one is primary, or dragging a *different* display, never moves where the primary itself draws -- but its own rectangle cannot be dragged: the dropdown is the one reliable way to change it, since a mouse click precise enough to land on a specific terminal cell with *no* movement at all is not something to depend on, over ssh least of all. Nothing else is kept that a fresh read of hold clients cannot recompute -- the same as every other pane's row list is rebuilt every frame -- except the drag itself, which is this window's own gesture in progress and belongs nowhere else, and is frozen against hold clients while it is happening: re-reading mid-drag would have the dragged rectangle's own base position shift under the live preview the moment the release this same drag ends in reaches the server.
control-panel/filetypesFile Types0.99.168the Control Panel pane for dt_handler's own extension-to- program table (DT_HANDLERS). Files' own Open With menu already reads it; this is where a mapping is added, changed or removed, rather than only through a dt_handler line in a script of your own -- which still works exactly as before, and is what dt_save now writes these back out as.
control-panel/keyboardKeyboard0.77the Control Panel pane for how keys reach a terminal window: whether the desktop's shortcuts work while a terminal has focus, and whether ctrl with a letter always goes to the program inside. Which key does what is the Shortcuts pane's, where every one can be changed.
control-panel/languageLanguage0.99.71the Control Panel pane for the language the desktop speaks and whether it orders right-to-left text itself (#68, ADR 0032). The languages listed are the catalogues there are, lang/<code>.json in the person's own folder or bundled; English is the source and always there.
control-panel/mouseMouse0.72the Control Panel pane for what the mouse does to a window: whether a plain side resizes it as well as a corner, whether a modifier click anywhere in its body moves it and which modifier, and what a double click on its title bar does. Every value is read by wm/input.hibr; this pane only changes the DT_* settings.
control-panel/networkNetwork Servers0.99.13the Control Panel pane for WebDAV servers (wm/remote.hibr): one row per server, each opening the dialog that changes it; Add Server; whether a remote file's copy is put back when it is saved; how long a server may take; and emptying the copies kept. Servers live in the dav module's own list, readable only by its owner -- this pane never shows a password.
control-panel/picturesPictures0.99.128the Control Panel pane for how a picture is drawn: half blocks, the same in grey, the character ramp, or real pixels where the terminal can place them. One setting reaches every picture the desktop draws -- the Image Viewer, the wallpaper, Mail's pictures, the film player and the browser -- since each passes DT_IMGMODE to the module that draws it.
control-panel/screensaverScreen Saver0.99.21the Control Panel pane for the screen saver (wm/saver.hibr): which one, or one at random, how many idle minutes before it starts, whether it locks the screen (wm/lock.hibr) once it has run a while, and a look at it now.
control-panel/shortcutsShortcuts0.79the Control Panel pane for every shortcut in one list: the desktop's own actions, then a launch shortcut for any app. Activating a row captures its next key; the ✕ beside a key, or delete or backspace on its row, clears it. wm/keys.hibr does all of it -- including asking before taking a key another action has. Every key the desktop acts on is here, the menu bar's, Copy's, Cut's and Paste's included. A key two actions share, which only a settings file edited by hand can arrange, is marked ⚠ on both.
control-panel/versionsVersions0.99.170which image each part of this desktop is actually running. About This Computer cannot answer that: it draws $HIBR_VERSION, which is the *desktop process's* own version, and a restart replaces that process and every module it loads while leaving the hold server's image exactly as old as the session (Gitea #42, #198). Three states, asked and named separately, because they move independently.
control-panel/windowsWindows0.99.154the Control Panel pane for how a window looks and where a new one goes: its frame, which side its buttons dock to, where its title sits, which glyphs the buttons are drawn with, Placement, and how wide a tiled workspace's main window is. How the mouse moves, resizes and double-clicks one is the Mouse pane's. Every value here is read by wm/frame.hibr; this pane only ever changes the DT_* settings, never the drawing itself.

What you are trusting

Everything here is a hibr script and runs with everything your own shell can do: there is no sandbox, and there are no signatures. TLS says which server the index came from, and the sha256 in the index says the bundle was not changed on the way — neither says who wrote it. A bundle may not carry a .so: a module is native code and comes with hibr itself.

The bundles are plain files in this repository: read one before you install it — that is the point of an app being a script. Every version ever published stays in bundles/, and the index offers the newest of each. The whole catalogue is one folder, so a mirror is a copy rather than a rewrite: apps index URL points at any copy of it.
